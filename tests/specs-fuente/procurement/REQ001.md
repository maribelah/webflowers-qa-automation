# REQ001 - Ingresar a New PO

## Prompt original

@Workspace

Necesito implementar un nuevo caso de prueba automatizado en este proyecto.

REQUERIMIENTO:
REQ001 - Ingresar a New PO

AMBIENTE:
El ambiente activo esta configurado en el archivo .env mediante:

AMBIENTE=BETA

La URL y las credenciales deben obtenerse exclusivamente desde:

src/utils/envConfig.ts

Utilizar:
- ENV.url
- ENV.usuario
- ENV.password

No usar process.env fuera de envConfig.ts.
No hardcodear URL, usuario ni contrasena.
No modificar el archivo .env.
No modificar envConfig.ts.

FLUJO:

1. Navegar a ENV.url.
2. Iniciar sesion reutilizando el LoginPage, fixture, task o metodo de autenticacion existente.
3. Esperar y validar que el dashboard haya cargado.
4. En el menu lateral, hacer clic en Procurement.
5. Expandir o seleccionar Products.
6. Hacer clic en New PO.
7. Esperar a que cargue la pantalla New Purchase Order.
8. Validar que se muestre el encabezado:

"Procurement - New Purchase Order [Products]"

9. Validar que esten visibles los siguientes elementos:
- Vendor
- Order Type
- Due Date
- Storage
- Save

## Analisis UI y localizadores

### Pantallas involucradas

- Login
- Dashboard
- Menu lateral de WebFlowers ERP
- Procurement - New Purchase Order [Products]

### Elementos y localizadores clave

- **Procurement:** `//div[@class='div-parent' and @title='Procurement']`
- **Products:** `//div[@class='div-parent' and @title='Procurement']/ul/li[3]/div`
- **New PO:** `//ul[@id='sub2_Products_11']/li[4]/div`
- **Encabezado:** texto exacto `Procurement - New Purchase Order [Products]`
- **Vendor:** `//label[contains(normalize-space(.),'Vendor')]`
- **Order Type:** `//label[contains(normalize-space(.),'Order Type')]`
- **Due Date:** `//label[contains(normalize-space(.),'Due Date')]`
- **Storage:** `//label[contains(normalize-space(.),'Storage')]`
- **Save:** `//button[@id='btnSave'] | //input[@id='btnSave']`

### Flujo esperado

1. Navegar al ambiente activo usando `ENV.url`.
2. Iniciar sesion con `AuthTasks.login(ENV.usuario, ENV.password)`.
3. Validar dashboard usando elementos del iframe header.
4. Navegar por `Procurement -> Products -> New PO`.
5. Esperar la pantalla New Purchase Order.
6. Validar encabezado y elementos requeridos.

### Notas

- Login reutiliza `LoginPage` a traves de `AuthTasks`.
- Los elementos del menu lateral viven en `iframe#left_page1`.
- Los elementos de New PO viven en `iframe#center_page`.
- No aplica archivo JSON porque el caso no ingresa datos funcionales.
- No aplica validacion en base de datos.
